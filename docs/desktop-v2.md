# Deberopa Desktop v2 사양

- 작성: 2026-10-15
- 상태: **소유자 결정 반영본**. 이 문서가 `docs/desktop-design.md`(Code - OSS 기반)를 대체한다.
- 배경: 0.3.0-beta.1의 Desktop은 Code - OSS를 고친 IDE였고, 에이전트는 옆 패널이었다. 소유자가 원한 것은 에이전트가 중심인 앱이었다. 형태가 달랐으므로 앱 셸을 새로 만든다.

## 1. 한 문장

**Deberopa CLI의 모든 기능을 담은, Orca·OpenCode Desktop·Codex 앱 같은 에이전트 중심 데스크톱 앱.** 필요할 때 파일을 열어 직접 고칠 수 있고, 이 PC의 로컬 LLM이나 같은 네트워크의 다른 컴퓨터에 있는 LLM으로 코딩 에이전트를 쓰는 일을 화면에서 편하게 할 수 있다.

## 2. 소유자 결정 (2026-10-15)

| 질문 | 결정 |
|---|---|
| 화면 구성 | 에이전트 중심. 왼쪽 프로젝트·세션, 가운데 작업 흐름, 오른쪽 diff·파일, 아래 터미널. **Orca처럼 탭으로 에이전트 세션과 파일 편집 등을 오간다** |
| 파일 편집 | 코드 편집기 탭(문법 강조, 검색·바꾸기, 여러 탭, 저장, 에이전트가 바꾼 부분을 diff로 보고 수락·되돌리기) |
| 원격 | 모델만 원격(추론은 다른 컴퓨터, 파일·도구 실행·세션은 Desktop이 설치된 컴퓨터). 같은 네트워크 자동 탐색 포함 |
| CLI | 위 기능은 CLI도 똑같이 지원한다 |

에이전트까지 원격으로 실행하는 방식(Desktop은 화면만)은 이번 범위가 아니다.

## 3. 화면

```
┌──────────────┬───────────────────────────────────────┬──────────────┐
│ 프로젝트     │ [세션 A ×] [세션 B ×] [src/app.ts ×] [+]│ 변경사항     │
│  ▾ deberopa  │ ┌───────────────────────────────────┐ │  3 files     │
│    · 세션 A  │ │ 대화 / 작업 흐름                   │ │ ─────────────│
│    · 세션 B  │ │  사용자 요청                       │ │ diff 미리보기│
│  ▸ other     │ │  도구 호출 카드, 권한 요청         │ │ [수락][되돌리기]
│              │ │  할 일                             │ │              │
│ 모델 / 서버  │ └───────────────────────────────────┘ │              │
│  ● 이 PC     │ 입력창  @파일  /명령  !셸             │              │
│  ● gpu-box   │                                       │              │
├──────────────┴───────────────────────────────────────┴──────────────┤
│ 터미널 (접기 가능)                                                  │
├─────────────────────────────────────────────────────────────────────┤
│ 모델 · 모드(compact/text-tools) · 컨텍스트 · tok/s · 슬롯 · 서버    │
└─────────────────────────────────────────────────────────────────────┘
```

- 탭 종류: 세션, 파일(편집기), diff, 터미널. 탭은 끌어서 순서를 바꾸고, 세션은 여러 개를 동시에 돌린다.
- 입력창, 권한 카드, 할 일, 되돌리기, 슬래시 명령, `!셸`은 지금 Desktop 패널과 CLI TUI에 있는 것을 그대로 옮긴다.
- 흑백, 장식 없음(AGENTS.md의 규칙과 같다). 글꼴은 시스템 기본.

## 4. CLI 기능 동등성

앱은 `deberopa serve`의 HTTP API와 이벤트 스트림만 쓴다. 서버에 있는 기능은 앱에서 쓸 수 있고, 앱에서 필요한데 서버에 없는 기능은 서버(=CLI)에 먼저 넣는다. 그래서 CLI와 Desktop이 어긋나지 않는다.

| CLI | 앱의 자리 |
|---|---|
| 세션 목록·재개·분기·압축·내보내기·공유 | 사이드바, 세션 탭 메뉴 |
| 에이전트, 모델 전환, 컨텍스트 사용량 | 입력창 위, 하단 상태줄 |
| 권한 요청, 할 일, 되돌리기 | 세션 탭 |
| 로컬 서버 감지, 도구 호출 점검, 모델 내려받기, 슬롯, tok/s | 모델/서버 패널, 상태줄 |
| 원격 호스트 등록·점검·탐색 (이번에 추가) | 모델/서버 패널 |
| MCP, LSP, 플러그인, 스킬, 신뢰, 인증 | 설정 |
| `deberopa pr`, `stats`, `export` | 명령 팔레트 |

## 5. 로컬과 원격 모델

연결 방식은 세 가지이고, 모두 "호스트"라는 하나의 개념으로 다룬다.

1. **이 PC**: Ollama, LM Studio, llama.cpp, vLLM, Opereta를 자동 감지한다(지금 있는 기능).
2. **같은 네트워크**: 사용자가 `검색`을 눌렀을 때만 사설 주소 대역(내 PC의 네트워크 인터페이스에서 계산한 /24)을 훑는다. 앱 시작이나 백그라운드에서는 아무것도 탐색하지 않는다.
3. **직접 지정**: 주소(`http://192.168.0.20:11434` 등)를 적는다.

호스트 프로필에는 이름, 주소, 선택적 API 키, 선택적 CA 인증서 파일이 들어간다.

- 탐색 중에는 **API 키를 보내지 않는다.** 응답이 401/403이면 "키가 필요한 서버"로 표시만 한다.
- 연결 점검: 응답 시간, 서버 종류, 모델 목록과 컨텍스트, 도구 호출 가능 여부(`deberopa local check`와 같은 점검), 인증 필요 여부, 인증서 오류의 종류와 해결 방법.
- TLS: 인증서·호스트 이름 검증을 끄는 옵션은 만들지 않는다. 자체 서명 인증서는 CA 파일을 지정해 신뢰한다.
- 평문 `http://`로 사설 주소가 아닌 곳에 키를 보내려 하면 거부한다.
- 호스트 프로필은 전역 설정(`provider.<id>`)에 저장하고, 프로젝트 설정에서는 무시한다(신뢰되지 않은 프로젝트가 요청을 다른 곳으로 보내지 못하게).

CLI: `deberopa remote [list|add|remove|check|scan]`. 서버: `/remote` 아래 같은 기능.

## 6. 기술 선택

| 항목 | 선택 | 이유 |
|---|---|---|
| 셸 | **Electron** | 저장소가 TypeScript 하나로 통일되어 있다. Windows 11과 Debian 13 양쪽에서 같은 렌더러가 돈다. Tauri는 용량이 작지만 Rust 도구와 Debian의 webkit2gtk에 의존해 두 플랫폼 검증 비용이 크다 |
| UI | React + 단순한 CSS | CLI TUI가 이미 React(Ink)다 |
| 편집기 | CodeMirror 6 | 가볍고, diff·검색·언어 지원이 있다 |
| 터미널 | xterm.js + 쉘 프로세스 | |
| 백엔드 | 번들한 `deberopa` 바이너리의 `serve`를 자식 프로세스로 실행 | CLI와 같은 코드 |
| 빌드 | Bun으로 렌더러 번들, electron-builder 또는 electron-packager로 패키징 | |
| 아이콘 | `assets/logo.png`에서 `app/script/make-icons.cjs`가 만든다. 원본은 정사각형이 아니고 원이 한쪽으로 치우쳐 있어, 원을 찾아 중앙에 맞추고 여백을 고르게 한 `build/icon.png`(창, 작업 표시줄), `icon.ico`(Windows), `icon.icns`(macOS)를 쓴다 | |

버리는 것: Code - OSS 빌드, 패치 3개, 300MB 패키지, 내장 확장 방식. 남기는 것: 서버, 세션·도구·로컬 모델 코드, 패널에서 만든 채팅 UI 로직(`desktop/extensions/deberopa-agent/media`)을 새 UI로 옮길 때 참고.

## 7. 단계

| 단계 | 내용 | 확인 |
|---|---|---|
| V0 | 원격 호스트 기능(코어, CLI, 서버, 시험) | **완료**. 진짜 Ollama를 LAN 주소로 점검·탐색·에이전트 실행 |
| V1 | Electron 셸, 번들 서버 기동, 사이드바와 세션 탭, 대화·도구 카드·권한 | **완료**. Windows·Debian 13 CI에서 앱이 실제로 떠서 시험 통과 |
| V2 | 파일 탭(편집기), diff와 수락·되돌리기, 터미널 | **완료**: 편집기 탭, diff 보기와 파일별 되돌리기, 터미널 탭 |
| V3 | 모델/서버 패널(로컬, 원격, 탐색), 상태줄 | 로컬 서버를 붙인 실사용 확인 |
| V4 | 설정(MCP, LSP, 플러그인, 신뢰, 인증), 명령 팔레트, 내보내기 | |
| V5 | 설치 프로그램, 업데이트 안내, 서명 | 소유자의 Windows 11 확인 |

Desktop과 CLI는 같은 버전, 같은 태그로 함께 낸다.

## 8. 위험과 확인하지 못한 것

- Linux(Debian 13)에서 Electron의 샌드박스가 처음 실행 때 거부될 수 있다(Code - OSS에서도 같았다). 설치 안내 또는 실행 스크립트에서 다뤄야 한다.
- Windows는 서명하지 않으므로 Smart App Control이 막을 수 있다. 소유자가 실제 PC에서 확인해야 한다.
- 같은 네트워크 탐색은 공유기·방화벽 설정에 따라 서버를 못 찾을 수 있다. 직접 지정이 항상 있어야 한다.
- 이 사양의 화면은 아직 소유자가 화면으로 확인하지 않았다. V1에서 실제 창을 보고 고친다.
